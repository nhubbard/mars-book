# Native bytecode assessment foundation

The generator tools/bytecode_lesson_cases.py preserves all 1,247 original direct-call trials, including image bytes, arena/descriptor choices, code and guest-stack subviews, salted sentinels, stack seeds, saved registers and continuations. A separate Python oracle validates a start set, then fetches/decodes guest bytes at each transition; its fixed outcomes agree with the original BigInteger DSL oracle. Groups contain 500 structural failures, eighteen bad targets, 421 completed outcomes and 308 runtime failures, with batches no larger than fifty. No implementation register/label or exact instruction count is prescribed.

Function format 23 and console format 8 already express the full interface; no production grader change is needed. Return expectations check full stack pointer/capacity and all five published outputs. Exit policies prohibit any later caller-data writes or out-of-view reads; the supported exit schema uses memory and access policies, while symbolic pointer comparisons occur at actual return. Twenty-three continuous callers distinguish initialization, actual report return, stored pair and exit.

Four distinct new public replacement sequences supplement, rather than publish, the original ten private rotations. Two algorithms at ordinary/wide data addresses pass all 1274 public cases (5,096 placements). All 24 historical faults have distinguishing rejections: 23 in original direct-call trials and the stale-boundary-map fault in the repeated-call domain. Both algorithms also pass original public DSL and all 12,720 private semantic cases/ten private rotations. The complete record-width helper passes 1,537 checks; ten planned register boundaries pass core probes. Full actual IDE and publication evidence belongs to bytecode-native-unit.md and native-bytecode-unit-01.

Finite tests establish these domains, not universal VM correctness or human usability. No new MARS production mechanism or API is introduced in this step.
