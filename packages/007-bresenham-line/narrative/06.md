# Paint before deciding whether to stop

The current point is a valid sample before the loop asks whether another sample is
needed. Store it first, then test both endpoint coordinates. When the endpoints
coincide, this ordering paints exactly that one cell and exits without entering
any update logic.

Testing only x is insufficient for a vertical line: its x agrees with the target
from the start. Testing only y has the corresponding problem for a horizontal line.
The reference exits only when both match. If x differs it skips the y test and advances;
if x matches it still checks y.

The `pixel_written` checkpoint belongs immediately after the store. At its first hit,
the working point and error still describe the starting sample. Later checkpoints
can show the same framebuffer prefix with coordinates already prepared for the next
sample. Naming these boundaries prevents a trace from mixing states.
