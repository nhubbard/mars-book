# Polling needs a fresh observation

A polling loop repeatedly reads a device until a condition becomes true. Here the
load must be inside the loop. If x is loaded once before the branch and never loaded
again, the comparison keeps seeing the old register value even while the robot moves.
A CPU register does not maintain a live link to the memory word from which it was read.

On the east leg the target is side and the other coordinate remains zero. Each loop
pass loads x, branches back when x differs from the target, and executes the explicit
`nop` delay slot. When x equals the target, the branch falls through to the stop store.
The branch's delay slot still executes on that final pass.

The same pattern works for the other legs after changing the feedback offset and
target. South watches y against side; west watches x against zero; north watches y
against zero. Choosing the wrong axis can make a test true before a side begins.
