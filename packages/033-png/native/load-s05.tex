\section{Step 5 Consume the read result}\label{png-load-s05}
Fill \texttt{load\_result}. A negative read result takes the failure-closing path. Zero branches to \texttt{load\_eof}. For a positive result, add the returned count to \texttt{\$s2}, retaining all address and count bits. The supplied code after \texttt{load\_progress\_ready} returns to \texttt{load\_read}.

In the partial-file recipe, the first positive result raises progress from zero to seventeen. The next request begins at destination plus seventeen and offers 98 bytes. Its zero result reports EOF; it does not reset the progress counter. This loader handles bytes only, so reaching EOF on seventeen bytes does not establish that the file is a complete PNG.

Use \texttt{s05-1} and stop before \texttt{load\_progress\_ready}.

\paragraph{Observe} At load\_progress\_ready, s2 is seventeen. A subsequent EOF preserves that count; no destination gap has been introduced.

\paragraph{Check} What destination should the second request use?
\begin{itemize}
\item[A.] The original destination plus seventeen.
\item[B.] The original destination plus 115.
\item[C.] The path address plus seventeen.
\end{itemize}
