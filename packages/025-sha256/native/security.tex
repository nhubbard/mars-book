\section{Interpret a matching fingerprint}
A matching digest establishes agreement with the supplied digest value for the checked
bytes, subject to the properties of the hash. It does not identify who supplied that
value. If a download and its expected digest are both replaced, recomputing the digest
alone does not reveal which source was authoritative. The route by which an expected
value is obtained is part of the surrounding system.

This project implements the unkeyed SHA-256 function. It does not implement a keyed
message authentication code, a digital signature or a password storage scheme. Those
constructions specify additional inputs and processing. For example, HMAC is a defined
keyed construction rather than an instruction to attach an arbitrary secret to an
otherwise ordinary file hash. Keep the hash primitive and its uses separate when
explaining what this program verifies.

The prototype's test results establish behavior over the stated fixtures. They do not
constitute cryptographic algorithm certification or a review of a production library.
The purpose of the assembly program is to make the data path, widths and interfaces
observable and testable.
