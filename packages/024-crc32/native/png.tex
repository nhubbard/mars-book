\section{Apply the update to a PNG chunk}
PNG uses the same CRC parameters, but its checked interval is a chunk's four type bytes
followed by its data. The chunk length and stored CRC field are outside that interval.
Even a chunk with no data has four type bytes to check. PNG stores the finalized CRC
most significant byte first. These choices are properties of the file format, separate
from the raw-state update interface.

For the zero-data \texttt{IEND} chunk, the input bytes are hexadecimal
\texttt{49 45 4e 44}. Their finalized CRC is \texttt{ae426082}, stored as
\texttt{ae 42 60 82}. A little-endian simulator word containing the numeric value
\texttt{ae426082} instead has memory bytes \texttt{82 60 42 ae}. A direct word
load from the four file bytes therefore does not produce the intended numeric value
under this chapter's little-endian memory configuration. Assemble the value from byte
loads and shifts, or use an explicitly justified byte-order conversion.

To check a chunk in parts, initialize once, update with the type, continue over every
data block, and complement once before comparison with the stored field. Changing
read boundaries does not change the checked interval. This exercise does not yet
validate PNG chunk ordering, decompression, image dimensions or the enclosing file.
It establishes the reusable checksum routine needed by later image work.
