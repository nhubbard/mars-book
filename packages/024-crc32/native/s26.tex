\section{Step 26 Distinguish errors, EOF and positive data}\label{crc-s26}

Check negative results before testing EOF. An error follows the supplied close-and-error path. Zero selects finalization, while a positive count falls through toward an update. Finalization is still temporary at this stage, so an EOF observation returns development status three until the success block is written.

\Needspace{11\baselineskip}
\subsection{Write and inspect}
Replace the marked temporary instructions in \texttt{f\_classify}. Retain surrounding labels and markers.

\MARSCodeLabel{MIPS assembly}
\begin{minted}[samepage=true]{mars-idea}
    bltz $v0, file_read_error
    nop
    beq $v0, $zero, file_finish
    nop
\end{minted}

Use \texttt{s26-1}, \texttt{s26-2}, \texttt{s26-3}. The CLI checks install explicit in-memory files and read/error controls. Ordinary IDE files do not force these short-read or failure conditions.

\subsection{Expected observation}
An immediate injected error returns zero/status two and closes the descriptor; positive reads have not yet changed the raw state.

\Needspace{11\baselineskip}
\subsection{Check your understanding}
Does a positive short read select EOF?

\begin{itemize}
  \item \textbf{A} Yes, whenever it is smaller than capacity.
  \item \textbf{B} Only for text files.
  \item \textbf{C} No; EOF is a zero result.
\end{itemize}
