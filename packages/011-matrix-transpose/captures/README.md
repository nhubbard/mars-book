# Verified native captures

Four reviewed figures combine twelve actual IntelliJ Light screenshots: the completed
ordinary three-by-five transpose, the first clipped tile, and the completed sixteen-by-sixteen
tiled run with fully associative and direct-mapped caches. Each figure combines the same
checkpoint's source, registers, memory, settings and counters. The original PNGs and raw
receipts are retained beside a rendered preview and editable native LaTeX annotations.

The cache has eight four-word blocks and 128-byte capacity in every view. The measured
access/miss pairs are 30/8, 24/7, 512/128 and 512/344. These are cold model observations,
not elapsed-time measurements. The caller's result store is excluded. At the intermediate
first-tile stop, `$v0` already holds the target count fifteen; twelve cells have been stored.

The separate authoring plugin depends on MARS and checks the native views before and
after each photograph. The capture batch used the actual `clean cleanSandbox runIde`
tasks. Independent host and core checks verify every output word and the ordered memory
accesses. The source/configuration identities, original pixel hashes and annotation bounds
remain in the receipts. An actual capture is not established by a recipe or a model check alone.

before its bounds instructions. The native condition `$t1 == 4` selects that visit. The three
default input rows leave the last output row untouched, matching the result of guided step 19.
