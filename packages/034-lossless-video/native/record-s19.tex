\section{Step 19: Bound the changed triples and advance}
Each changed pixel consumes three payload bytes. Compute three times the
changed count, compare it with the remaining payload bytes, and reject if it
does not fit. The admitted pixel bounds keep the product at most 12\,288, so
this multiplication cannot overflow the working register.

Fill \texttt{record\_payload\_bounds}. On admission, advance the byte cursor
by that product and the pixel cursor by the changed count. This validation pass
does not read the triples or apply XOR. The supplied loop reads another command
only while fewer than 4096 pixels have been covered. A zero triple is legal;
validation must not demand that every changed value is nonzero.

\paragraph{Observe} Prepare \texttt{s19-1} and stop before
\texttt{record\_payload\_ready}. At the first \texttt{record\_payload\_ready}, the product in
\texttt{\$t4} is three, the byte cursor is source plus 23, and the pixel
cursor is one. The final skip-only command remains to be checked.
