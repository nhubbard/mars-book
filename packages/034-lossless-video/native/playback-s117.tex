\section{Step 117 Wait only for a positive remainder}
Fill \texttt{vp\_sleep}. Subtract current time from the deadline only on the path where current time is smaller. Pass the positive difference to service thirty-two. The difference is at most the admitted duration, no greater than 1000 milliseconds, because the preceding interval already reached its deadline and time has not moved backward.

After the service returns, sample time again. A sleep may return early or overshoot. For example, samples 1010, 1035 and 1040 cause requests of thirty and then five milliseconds for the same deadline 1040. No zero or negative request is needed.

Use \texttt{s117-1} and stop before \texttt{vp\_sleep\_requested}.

\paragraph{Observe} Under the waiting timeline, the first request is thirty milliseconds. An early return causes only the remaining positive wait to be requested next.

\Needspace{8\baselineskip}
\paragraph{Check} Why sample again after sleeping?
\begin{enumerate}[label=\Alph*.]
  \item Host sleep completion does not guarantee that the exact deadline was reached.
  \item Every sleep changes the file's frame count.
  \item The time service returns a record checksum.
\end{enumerate}
