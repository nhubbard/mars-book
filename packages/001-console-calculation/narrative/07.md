# A register can change roles

A register name does not fix the meaning of every value stored there. Before
the input request, `$v0` holds the selector 5. After the request returns, it holds
the integer that was read. The service contract defines that transition.

This is similar to a function interface with a specified result location, but
the transfer is explicit in assembly. Later instructions read the returned value
from the named register. Loading a new service number into the same register
would replace the input, so the arithmetic must use or preserve it first.

When tracing the program, record both a register's value and its current purpose.
The annotation “`$v0 = 5`, service selector” is more informative than recording
only the number.
