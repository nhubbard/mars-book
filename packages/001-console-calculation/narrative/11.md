# Preserve a value across interface setup

The answer is now in `$t0`. The next operations prepare a string-printing
request, so `$a0` becomes an address and `$v0` becomes a service selector again.
Keeping the answer in `$t0` lets that setup proceed without losing the value to
be printed later.

This is a small example of managing the lifetime of a value. The result must
remain available from the end of the arithmetic through the printing of the
answer prefix. Each write in that interval should have a stated purpose.

A correct printed prefix does not establish that the number is still available.
The debugger's register view lets us check both parts independently. This
reference deliberately uses `$t0` so that its intermediate observations have a
consistent name.
