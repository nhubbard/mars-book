# Serialize the fixed header in file order

Author e_header to write the four magic bytes, width and height in big-endian order, then the retained channels and colorspace bytes. Advance the destination cursor exactly fourteen bytes. The input framebuffer is still unread. This construction is the inverse of the byte-wise header interpretation; a native little-endian metadata copy would not produce the same file.

Observe: The destination contains the accepted fourteen-byte header and s2 points just after it. All later destination bytes are sentinels.

Use observation s37-1. Native prose and typeset quizzes are in native/s37.tex.

Check: How are dimension bytes ordered in the output?

**A** The simulator’s native word order.
**B** Least significant byte first.
**C** Most significant byte first.

Hint 1: The metadata’s in-memory layout is not the file header’s layout.
Hint 2: Emit four positioned bytes per dimension and only one byte per validated descriptive flag.
