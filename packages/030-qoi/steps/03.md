# Reject dimensions before multiplying them

Author b_domain to reject zero or a value above sixty-four in either field. These decisions precede the pixel-count multiplication. Branch to the supplied invalid return for a rejected field, leaving v1 zero there. Use unsigned comparisons so that a field with its high bit set cannot pass a signed less-than check as a negative dimension.

Observe: The eight-by-one argument reaches the checkpoint unchanged in t1 and t2. Invalid dimensions take the supplied status-one return.

Use observation s03-1. Native prose and typeset quizzes are in native/s03.tex.

Check: Why must a high-bit dimension fail?

**A** Its unsigned value exceeds the local limit.
**B** It describes a negative number of transparent pixels.
**C** It is an alternative spelling of zero.

Hint 2: Test nonzero and unsigned less-than sixty-five before computing the product.
