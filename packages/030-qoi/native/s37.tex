\section{Step 37 Serialize the fixed header in file order}\label{qoi-s37}
Author \texttt{e\_header} to write the four magic bytes, width and height in big-endian order, then the retained channels and colorspace bytes. Advance the destination cursor exactly fourteen bytes. The input framebuffer is still unread. This construction is the inverse of the byte-wise header interpretation; a native little-endian metadata copy would not produce the same file.

Work in \texttt{e\_header}; use \texttt{s37-1} and stop at \texttt{after\_e\_header}.

\paragraph{Observe} The destination contains the accepted fourteen-byte header and \texttt{s2} points just after it. All later destination bytes are sentinels.

\paragraph{Check} How are dimension bytes ordered in the output?
\begin{itemize}
\item[A.] The simulator’s native word order.
\item[B.] Least significant byte first.
\item[C.] Most significant byte first.
\end{itemize}
