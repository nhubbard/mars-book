\section{Compare application fields before serialized bytes}
The fifty-two-byte input and thirty-seven-byte deterministic output represent the same
required counter, identifier and readings. Their full maps are different because the
input contains optional key three. Compare the projected required fields when checking
that transformation. Do not assert that the input and output byte strings are identical.

A second decode of the deterministic result must recover the same flat-record values.
Encoding that recovered record again must produce the same thirty-seven bytes. This
checks the writer's chosen representation after the first projection. It does not
establish malformed-input handling or the absence of writes on an earlier failure.

Use an independent CBOR implementation to inspect actual output bytes as another
observation. Its supported types and default policies can be broader than this
exercise. For example, a library accepting indefinite containers or choosing one value
from duplicate keys does not authorize the local decoder to do so. Keep a strict
profile checker and general interoperability observations separate.
