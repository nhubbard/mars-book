# Signed declarations and unsigned masks

The starter uses byte initializers within the assembler's signed range to
avoid truncation warnings. For example, the initializer −37 stores the pattern
0xdb, and −1 stores 0xff. These patterns can also be interpreted as the unsigned
values 219 and 255. The byte's stored bits do not identify one interpretation as
its permanent meaning.

`lbu` supplies the unsigned interpretation when loading the row into a register.
It zero-extends the byte: the register's low eight bits contain the stored
pattern and its other bits become zero. A row with its high bit set therefore
remains a mask in the range 128 through 255. A signed byte load, `lb`, would
sign-extend instead.

The drawing algorithm examines bits, so unsigned loading keeps its working
values easy to reason about. Each source row is always between zero and 255,
including rows whose declaration was written as a negative signed byte.
