# Branch direction is distinct from branch prediction

The counter uses the core's branch-decision metadata. Taken and not-taken outcomes both
contribute to the total. An always-taken `beq` is still a branch decision. A `jal`, j, or `jr`
is a jump rather than a branch under this definition, and its delay-slot `nop` contributes
an instruction without adding a branch.

The measured selection range executes 115 branches on each of the three eight-item
workloads. Its scan structure is fixed, but outcome directions vary. Sorted input has
79 taken and 36 not taken; reversed input has 59 and 56. Those counts describe decisions,
not mispredictions, pipeline flushes, or physical instruction latency.

Forward counters do not subtract events when backstep undoes state. Re-executing an
instruction adds a new forward event, matching the IDE's counting convention. The reported
measurements use fresh runs with no replay. Correctness cases do not require a student
implementation to reproduce the reference's instruction or branch totals.
