# Separate algorithm-range work from the visualizer total

The total forward counter includes setup, every render, all sorting control, and exit.
A second counter filters instruction addresses from `sort_begin` up to but excluding `sort_end`.
The renderer body is outside that interval, so its instructions are excluded even when a
call originates within it. Caller argument preparation, metadata stores, `jal`, and its `nop`
remain included when their own addresses are inside the interval.

This range is a concrete measurement boundary, not an assertion that every included
instruction is a pure comparison or exchange. The table labels it accordingly. The range
uses full instruction addresses and core event data; it does not classify source lines
or guess branch opcodes.

On the default shuffled input, whole-run counts are 26,197 for insertion and 10,111 for
selection, while the selected ranges contain 716 and 686 instructions. The whole visualizer
has much more rendering work because insertion publishes seventeen exchanges and selection
five. Naming both scopes prevents that display cost from becoming an unsupported claim
about an abstract sorting algorithm.
