    \small
    \begin{enumerate}
      \setlength{\itemsep}{0pt}
            \setlength{\parsep}{0pt}
      \item The stop at \texttt{validate\_bad} precedes the instruction that selects status two. The validator has detected an error; its return and the caller publication have not executed.
      \item \texttt{s3 = 33} is the value of the second character, \texttt{h}. In six bits it is \texttt{100001}. Two padding characters leave only its top two bits available for decoded data.
      \item \texttt{t0 = 1} is that sextet masked with 15. Its unused low four bits are \texttt{0001}, so this chapter\textquotesingle s canonical-input contract rejects the text.
      \item The source is \texttt{5a 68 3d 3d}, or \texttt{Zh==}. Canonical \texttt{Zg==} uses sextet 32, whose unused bits are zero. Both can yield the same first decoded byte if those bits are simply discarded.
      \item The destination still contains \texttt{a5}. Validation has not written a partial decoded result. Continuing through the error return yields status two and written count zero.
      \item The first control row contains capacity 8192 and saved status $-1$, followed by alignment bytes. The next begins with eight \texttt{ff} bytes for the saved written count $-1$. These caller fields remain unchanged until the caller resumes after return.
    \end{enumerate}
