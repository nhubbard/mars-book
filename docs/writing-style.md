# Writing style for the MARS book

Use sentence case for headings and captions. Introduce technical terms at first use.
Use consistent terminology, spelling, and number notation. Write connected paragraphs;
use a list when its items are a sequence or a set, and a table when readers need to
compare fields. Attribute quotations and keep claims within the evidence. These rules
adapt the [Wikipedia Manual of Style](https://en.wikipedia.org/wiki/Wikipedia:Manual_of_Style).
Exercises retain direct instructions to the student because this is a textbook.

Use [Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)
as an editorial checklist. Remove inflated claims, vague attribution, superficial
interpretation, repeated rhetorical contrasts, ornamental phrasing, and formulaic
summaries. Prefer the ordinary name of an operation to a series of synonyms. The
presence of a listed feature does not establish who wrote a passage.

## Explanations in this book

Describe the operation before assigning it wider significance. Name its inputs, the
state it changes, and the boundary at which the reader can observe the result. A worked
example should show a concrete value or byte sequence. Explain an error by tracing the
incorrect write or request. Avoid praise for the exercise and promises about mastery.

Assembly examples use code formatting for mnemonics, register names, labels, and literal
source text. State whether a number is decimal or hexadecimal when ambiguity matters.
Keep a statement about arithmetic width beside the instruction it describes. Distinguish
an address, the bytes at that address, and an interpretation of those bytes.

The author may revise any source passage. Human material can be placed between any
reading segments. Record material AI edits to human writing in the editorial log when
requested, without adding editorial narration to the student's lesson.
