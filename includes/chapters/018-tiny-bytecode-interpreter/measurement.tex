\section{Measure the complete native call}\label{vm-measurement}
The guided implementation records boundaries in one register. The alternative uses a
sixty-four-byte private map, clears it on every call and marks starts with byte stores.
It also groups some opcode classifications differently. This comparison measures two
complete implementations; it does not isolate the causal cost of a boundary map.

The full default retires thirty-three guest instructions. The self-branch retires
sixty-four before yielding; its image is \texttt{JMP 0}. The sixty-four-byte scene
starts with \texttt{JMP 63} and otherwise contains halt bytes. It retires a jump and
a halt. The invalid scene changes the default JZ target to six and uses zero budget.
Both validation passes still precede execution, so it returns a target failure with
no retirements. The one-halt scene also illustrates a fixed setup tradeoff: the byte
map's complete call uses more work there despite using less for the default image.

Counts include the native prologue, validation, execution, publication and restore.
They exclude caller setup, assembly, session construction and program exit. Private
map and native stack accesses are outside the image-read columns. The figures describe
simulated instructions, not host cycles or elapsed time. Equivalent implementations
may use different read widths and need not match these counts.

A retained map is valid only for the contents from which it was derived. The caller
may replace an image at the same pointer and length between calls. Reusing a previous
map on that evidence alone can accept an operand byte as an instruction start. Clear
and rebuild private derived state on every fresh call, or prove a content-valid cache
protocol that preserves the specified behavior. Checking only the default program
cannot establish that protocol.
