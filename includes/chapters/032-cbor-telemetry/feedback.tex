\section{Choose feedback for the observation being tested}
Use a guided check while working through a named step. From the construction directory,
run \texttt{java -jar /path/to/cli.jar grade checks/construction/s26.kts working.asm}.
The script installs the step's input data and caller controls, then stops before its
published checkpoint. It does not require the rest of the routine to be complete.
The same check can be rerun after later work is finished. Step 55 has two caller cases
because it compares short encode capacity with a trailing-byte decode failure.

For a completed routine, choose its final domain instead, for example
\texttt{java -jar /path/to/cli.jar grade checks/decode.kts working.asm}.
These checks compare results and caller storage through the public interfaces. They
accept different private frames, constants, register choices and algorithms. The guided
checks instead follow the particular registers and candidate locations illustrated in
this construction. A failed guided-state comparison does not by itself establish that
an independently organized completed solution violates its public contract.

Each script is self-contained and supplies expected observations from a host model.
The tests include failure output preservation, full-width saved state and selected
memory access intervals. Passing finite cases provides evidence for those cases;
instructors may add further inputs under the same published contract. Construction
status four reports an unfinished body and does not satisfy a completed-entry check.
