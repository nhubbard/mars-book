\section{Step 7 Handle an empty window before the
  loop}\label{005-seven-segment-counter-s07-step-7-handle-an-empty-window-before-the-loop}

A zero count requests no transactions. The pre-test branches directly to
the existing exit. \texttt{beq} is a retained delayed branch, so its
following \texttt{nop} executes whether the branch is taken or not.

\subsection{Write or
  inspect}\label{005-seven-segment-counter-s07-write-or-inspect}

Append the zero-count test and its explicit delay slot.

\MARSCodeLabel{MIPS assembly}
\begin{minted}{mars-idea}
    beq $s3, $zero, done
    nop
\end{minted}

\subsection{Expected
  observation}\label{005-seven-segment-counter-s07-expected-observation}

The empty window exits before the table load and port store. A nonempty
window continues to the loop body.

\subsection{Check your
  understanding}\label{005-seven-segment-counter-s07-check-your-understanding}

Why test the count before the first store?

\begin{itemize}
  \tightlist
  \item
        \textbf{A} An empty window must produce no I/O writes.
  \item
        \textbf{B} Every branch must always be taken.
  \item
        \textbf{C} A zero count names the first display port.
\end{itemize}
