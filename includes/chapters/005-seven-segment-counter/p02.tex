\section{Keep the device pointer
fixed}\label{005-seven-segment-counter-p02-keep-the-device-pointer-fixed}

The pixel and sprite programs advanced destination pointers because
different addresses named different cells. This counter repeatedly
updates one register. The device pointer stays fixed while the table
cursor advances through its selected bytes.

That distinction explains a common error: incrementing the device
pointer after an output. The next byte would go to the left display,
then keypad control, then timer control. A recognizable first glyph
would not make those later transactions correct.

The guide uses \texttt{dli} to express the complete pointer as
00000000ffff0010 in a 64-bit register. It is an assembler
pseudo-instruction and can expand into more than one machine
instruction. The store boundary is the useful observation point,
regardless of that expansion.
