  \begin{minipage}{\linewidth}
    \small
    \begin{enumerate}
      \setlength{\itemsep}{2pt}
            \setlength{\parsep}{0pt}
      \item The blue \texttt{nop} at \texttt{wrap\_ready} follows the supplied wrapping routine\textquotesingle s return. The caller has already saved both saturation results. It has not yet stored \texttt{wrapped\_count}. Both output arrays are complete.
      \item \texttt{\$v0 = 16} is the current processed count. The wrapping routine explicitly returns \texttt{\$v1 = 0}. The saved \texttt{clipped} word remains 6 from the earlier saturating call; each result must be read with its call boundary.
      \item The saturated slice begins at \texttt{0x10010194} and occupies 32 bytes. It retains $-32768$ and 32767 for already representable endpoint sums as well as for clipped sums. The clipping count therefore depends on exact input sums, rather than counting endpoint values in this array.
      \item The wrapping slice begins at \texttt{0x1001025c}. Positive 40000 stores \texttt{40 9c}, interpreted as $-25536$; $-40000$ stores \texttt{c0 63}, interpreted as 25536. Wrapping retains the low sixteen bits instead of selecting a signed endpoint.
      \item The caller row contains count 16, processed 16, clipped 6 and wrapping count 99. Continuing through \texttt{wrap\_continue} copies the current \texttt{v0} into the final word. It preserves the earlier processed and clipping results.
    \end{enumerate}
