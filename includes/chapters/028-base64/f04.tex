    \small
    \begin{enumerate}
      \setlength{\itemsep}{0pt}
            \setlength{\parsep}{0pt}
      \item At \texttt{after\_dec16\_compact}, the final byte selection is complete. The next region stores the vector into private scratch before copying the twelve-byte result.
      \item \texttt{w5} holds numerical sextets. \texttt{w6} combines each quartet into three bytes followed by a zero byte. The four filler positions separate groups; they are not decoded input.
      \item \texttt{w7}, read from lane zero upward, contains \texttt{01 96 b3 d3 df bf 03 3d 3d fb f6 5a}, then four zeros. Those last four lanes appear at the left of the whole-vector hexadecimal display. Compaction has removed the inter-group gaps.
      \item The sixteen unpadded characters \texttt{AZaz09+/Az09+/Za} decode to the same twelve-byte input used in the previous encoder figure.
      \item The caller destination still contains \texttt{a5}. The four zero lanes do not authorize a sixteen-byte caller store; the kernel publishes exactly twelve decoded bytes.
      \item The private sixteen-byte frame begins at \texttt{0x10015018} and is still poisoned. Resuming stores all sixteen vector bytes there, then copies twelve individual bytes to caller output. The neighboring alphabet bytes are outside that frame.
    \end{enumerate}
