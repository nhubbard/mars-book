\section{Control a moving model through
  feedback}\label{006-marsbot-square-p00-control-a-moving-model-through-feedback}

The counter sent a sequence of masks to a fixed port. MarsBot adds a
device whose state changes between successive program instructions. The
program tells it which way to face and whether to move; the robot then
publishes coordinates that the program can read. Drawing a side becomes
a small control problem: issue a command, observe progress, and stop at
a target.

The distinction matters even in a simulator. A register containing a
target coordinate is a statement of intent. A feedback word reports
where the connected device has reached. Confusing the two leads to
programs that write a plausible answer into memory without causing the
corresponding device behavior. This chapter uses the actual pen trail as
evidence of drawing, rather than trusting a list of corners written by
the program.

The first square uses four explicit legs. Their repeated structure makes
the axis, direction, target, and stopping condition visible. Once those
parts are understood, a command table can remove duplication while
retaining the same device contract.
