\section{Test the control assumptions, not a single
picture}\label{006-marsbot-square-p11-test-the-control-assumptions-not-a-single-picture}

The default sixteen-pixel square is only one input. A one-pixel side
stresses the first movement tick, and a longer side exercises repeated
polling. Changing the instructions-per-tick setting exposes a busy-wait
program calibrated to one clock. The tests vary both dimensions while
checking the same geometric result.

The grader observes the same device model used in the IDE at the same
completed- instruction boundary. It also watches the input and
coordinate words for execution stores, including modifications that are
later restored. Ordinary device publication and instructor setup are not
CPU writes under that check.

These checks establish model behavior. They do not establish that the
IDE opened the correct execution tab, rendered a path, or applied the
intended light theme. The planned capture recipes retain those separate
assertions so future screenshots can be tied to a known device state and
a visible UI.
