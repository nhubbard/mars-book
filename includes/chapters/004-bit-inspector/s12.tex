\section{Step 12 Print
binary}\label{004-bit-inspector-s12-step-12-print-binary}

Service 35 prints exactly 32 binary digits for the low word, without a
0b prefix. The final newline is still a separate request. Printed digit
order runs from the most significant bit on the left to the least
significant bit on the right.

\subsection{Write or
inspect}\label{004-bit-inspector-s12-write-or-inspect}

Append the final report line before the supplied exit.

\MARSCodeLabel{MIPS assembly}
\begin{minted}{mars-idea}
    la $a0, binary_msg
    li $v0, 4
    syscall
    move $a0, $s0
    li $v0, 35
    syscall
    la $a0, newline
    li $v0, 4
    syscall
\end{minted}

\subsection{Expected
observation}\label{004-bit-inspector-s12-expected-observation}

The default binary line contains 32 ones. A sample of one would contain
31 leading zeroes and one final one.

\subsection{Check your
understanding}\label{004-bit-inspector-s12-check-your-understanding}

Is this printed left-to-right order the same as increasing byte
addresses in little-endian memory?

\begin{itemize}
\tightlist
\item
  \textbf{A} No; numeral order and memory byte order are different
  conventions.
\item
  \textbf{B} Yes; the first printed digit is always at the lowest memory
  address.
\item
  \textbf{C} Binary output changes the selected memory byte order.
\end{itemize}
