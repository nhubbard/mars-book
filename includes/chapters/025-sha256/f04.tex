    \small
    \begin{enumerate}
      \setlength{\itemsep}{0pt}
            \setlength{\parsep}{0pt}
      \item The stop at \texttt{main\_done} follows the file routine return and precedes the caller status store. This is an ordinary host file containing the published recipe bytes; no forced short-read or error fixture is installed.
      \item \texttt{v0 = 0} is the successful file status. The digest is returned through the output memory interval, not this register.
      \item The two rows contain all thirty-two digest bytes in their serialized order: \texttt{fe544af2 3f2b64c6 d5f5fc0d 454a9cf8 df1bc76a be3d0729 20e66d4c e0f193a4}. A host \texttt{hashlib.sha256} calculation over the exact file agrees.
      \item The final positive read supplies \texttt{8c d5}. The following \texttt{1d 66 b0 f9 42} bytes remain from the previous use of the seven-byte buffer. Only the returned byte count is consumed; old suffix bytes are not new input.
      \item The controls show source length sixty-five, file mode one and capacity seven. Saved \texttt{status} is still $-1$ at this boundary; the caller writes the current zero return afterward. Ordinary host reads need not reproduce the separate CLI recipe\textquotesingle s forced one-byte read schedule.
    \end{enumerate}
