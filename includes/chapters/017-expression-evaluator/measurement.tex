\section{Measure complete parser calls}\label{expression-measurement}
The two verified designs share primary, unary and arithmetic helpers. The reference
uses separate term and expression loops. The alternative uses a precedence threshold
for binary operators. Each measurement runs a complete public function call on the
same bytes, excluding caller setup, assembly, session construction and program exit.

The chain input contains thirty-two digit-one operands. The unary input has sixty-three
minus signs followed by one. The group input encloses one in thirty-one pairs of
parentheses. The final two inputs are \texttt{2147483647+1?} and \texttt{1/(2-2}.
The separate-loop design uses fewer instructions on the addition chain, while the
threshold design saves work for nested groups. Neither result establishes a universal
winner. Input reads can repeat the same byte as several rules inspect a boundary.
Private stack accesses are outside the input-read column. An equivalent parser may
use another read width or traversal and produce other counts without violating the
contract; every byte in each load must still fit inside the input slice.

An optimization must preserve intermediate overflow checks and diagnostic priority.
Combining arithmetic algebraically or validating all syntax first can change those
results even when successful examples still agree. Measure work only after checking
that complete behavior, and state the expression shape with the measurement.
