    \small
    \begin{enumerate}
      \setlength{\itemsep}{2pt}
            \setlength{\parsep}{0pt}
      \item This fixture changes only the input bytes, their arena padding and the supplied length. The next instruction remains the same \texttt{expression\_ready} marker after the public function returns. The offered input is \texttt{1/(2-2}, without its closing parenthesis.
      \item \texttt{\$v0 = -1} reports syntax failure. \texttt{\$v1 = 6} is the end offset, not an expression value or the denominator. The inner subtraction yields zero, but the group still requires \texttt{)} before it can return successfully. That missing close is reported before the outer division can consume a successful right operand.
      \item The six input bytes begin at \texttt{0x10010004}: \texttt{31 2f 28 32 2d 32}. Offsets 0 through 5 name those bytes. Offset 6 is the boundary at \texttt{0x1001000a}; the mapped zero there belongs to padding and is not read. End-of-input syntax detection is a length comparison, not a search for a zero terminator.
      \item The row at \texttt{0x100100d0} contains length, caller status, caller second result, and the final guard. Bytes \texttt{63 00 00 00} encode decimal 99, the initial value of both result words. The evaluator returns through registers and leaves caller data read-only. Continuing past \texttt{expression\_continue} lets the caller replace those two words; exit later reuses \texttt{\$v0} for its service number. Length is 6. The status and result words remain 99 even on this error return; they are not parser progress fields. After continuation, the caller stores $-1$ and 6 there.
    \end{enumerate}
