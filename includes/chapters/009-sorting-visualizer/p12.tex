\section{Bound arithmetic assumptions and state the test
domain}\label{009-sorting-visualizer-p12-bound-arithmetic-assumptions-and-state-the-test-domain}

The alternative keeps a moving insertion pointer instead of rebuilding
one address at each comparison. Its selection comparison uses a
difference-sign test. Active operands are from \ensuremath{-}4 through 3, so their
difference lies from \ensuremath{-}7 through 7 and cannot overflow a signed word.
That justification belongs beside the optimization.

For unrestricted signed words, subtract-and-test can overflow and
disagree with a true signed comparison. Extending the input domain would
therefore require changing that alternative or proving an appropriate
bound. The display encoding would also need a new scale; eight rows
cannot distinguish every 32-bit value.

The private suite exhausts prefixes of length zero through five over
\{\ensuremath{-}1,0,1\}, tests all 64 two-item pairs from the full active domain, and
adds mixed lengths and named orderings. It does not exhaust all
eight-item arrays. Function tests separately vary argument pointers,
lengths, and caller registers. These bounded claims make the evidence
useful without turning a finite test set into a proof for a different
interface.
