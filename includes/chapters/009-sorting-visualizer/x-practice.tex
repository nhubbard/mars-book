\section{Practice and
extensions}\label{009-sorting-visualizer-x-practice-practice-and-extensions}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Trace the default first exchange in each algorithm and compare the
  resulting arrays.
\item
  Count the inversions in {[}1,0,\ensuremath{-}1,0{]}. Predict adjacent-exchange
  insertion\textquotesingle s swap count.
\item
  Explain why loading one value, overwriting the other slot, and then
  loading that overwritten slot loses data. Repair the exchange without
  changing multiplicities.
\item
  Derive the first white row for value \ensuremath{-}2 and the address of frame cell
  (7,7).
\item
  Call the renderer with a pointer to the second word and length three.
  Identify which source values are active and which saved registers must
  remain unchanged.
\item
  Trace {[}2a,2b,1{]} as records. State the identity assertion needed to
  test stability.
\item
  Compare the whole and range metrics for reversed input. Explain why
  render cost grows with the number of published exchanges.
\item
  Design a shift-based insertion or unrestricted signed-word extension
  separately. Specify its intermediate-state policy, arithmetic
  comparison, display encoding, record width, and grading changes before
  implementing it.
\end{enumerate}

A nested helper call inside render also changes its return-address
obligations. State how the incoming continuation would be preserved
