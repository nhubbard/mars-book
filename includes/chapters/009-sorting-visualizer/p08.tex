\section{Treat duplicate identities as a separate
  question}\label{009-sorting-visualizer-p08-treat-duplicate-identities-as-a-separate-question}

A stable sort retains the relative order of records with equal keys. The
current input stores only key values, so it cannot reveal whether two
equal items exchanged identities. A tagged thought experiment makes that
distinction visible.

Selection on {[}2a,2b,1{]} first exchanges the one with the first two,
producing {[}1,2b,2a{]}. It chose the first minimum and the numeric
values are correctly sorted, yet the two equal keys changed relative
order. The nonadjacent exchange caused the change. Strict adjacent
insertion does not move equal keys across one another.

This chapter checks value permutations and the declared exchange
sequence. It does not claim to prove record stability from
indistinguishable numeric duplicates. A record-sorting extension should
store key and identity together, move whole records, and check identity
order in addition to key order and multiplicities.
