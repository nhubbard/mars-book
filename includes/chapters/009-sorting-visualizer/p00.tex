\section{Sorting has two independent
  obligations}\label{009-sorting-visualizer-p00-sorting-has-two-independent-obligations}

An ascending array has no adjacent pair in decreasing order. That
condition alone is not enough: the result must also preserve the input
values and their multiplicities. Replacing every item with the same
number can satisfy order while destroying the data. A correct sort
establishes order through a permutation of the original active prefix.

The visualizer makes intermediate permutations observable. Main
publishes the original array, each complete algorithm exchange, and a
final completion state. The frame must agree with the actual array at
each boundary. A claimed swap counter or a log of intended arrays is not
a substitute for those observations.

This project compares an adjacent-exchange insertion variant with
first-minimum selection. For further reading, Sedgewick and Wayne
provide their
\href{https://raw.githubusercontent.com/kevin-wayne/algs4/master/src/main/java/edu/princeton/cs/algs4/Insertion.java}{insertion}
and
\href{https://raw.githubusercontent.com/kevin-wayne/algs4/master/src/main/java/edu/princeton/cs/algs4/Selection.java}{selection}
implementations. The MARS exercise omits selection self-exchanges and
the final single-item pass, and defines its own publication interface.
Its measured totals refer to the code and fixtures here.
