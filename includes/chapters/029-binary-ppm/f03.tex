\small
\begin{enumerate}
\setlength{\itemsep}{0pt}
\setlength{\parsep}{0pt}
\item At \texttt{after\_e\_maxval}, the header-writing steps are complete. The next region would serialize pixel components, but at this lesson stage \texttt{e\_rgb} still branches to the development return.
\item \texttt{t3 = 0x100172ab} points eleven bytes past the destination base \texttt{0x100172a0}. It is the address for the first raster byte, not the number of bytes written.
\item The eleven output bytes are \texttt{50 36 0a 32 20 32 0a 32 35 35 0a}: \texttt{P6}, LF, \texttt{2 2}, LF, \texttt{255}, LF. Maxval is three ASCII digits, not a single binary \texttt{ff} byte. Exactly one final LF separates this header from the raster. The following \texttt{a5} bytes remain untouched.
\item The framebuffer still holds the four original color words. The next lesson extracts red, green and blue from each word and writes three output bytes per pixel; the fourth byte of a framebuffer word is not a PPM sample.
\item The caller\textquotesingle s status and count remain $-1$. Mode two selects encoding, and the displayed source byte-count control is not the serialization cursor. Resuming this unfinished stage returns development status four and count zero while retaining the header prefix.
\end{enumerate}
