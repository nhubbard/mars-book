\small
\begin{enumerate}
\setlength{\itemsep}{0pt}
\setlength{\parsep}{0pt}
\item The stop at \texttt{parse\_return} is in the caller, after \texttt{ppm\_parse} has returned. The highlighted branch has not run; the caller has not yet copied the return values into its saved controls.
\item \texttt{v0 = 0} reports successful parsing. \texttt{v1 = 4} is the number of pixels, $2\times2$. It is neither the eleven-byte header length nor the twenty-three-byte file length.
\item The descriptor stores width and height as two four-byte little-endian integers, followed by an eight-byte offset. Its bytes represent width two, height two and offset eleven. The offset is measured from the start of the source file, not from the descriptor.
\item The first eleven source bytes spell \texttt{P6}, LF, \texttt{2 2}, LF, \texttt{255}, LF. Twelve RGB bytes follow. In the second row, the last three \texttt{ff} bytes finish the white pixel; the following \texttt{a5} bytes are backing storage outside the logical file.
\item The control rows still contain status $-1$ and count $-1$. The second row contains mode zero and source byte count twenty-three. The parser has published metadata, but has not produced framebuffer pixels or changed the caller\textquotesingle s result fields.
\end{enumerate}
