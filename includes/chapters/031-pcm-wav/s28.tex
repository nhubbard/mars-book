\section{Step 28 Accept an empty stream with a real container}\label{pcm-wav-s28}
Parse the empty18 recipe: mono PCM at 8000 Hz, an eighteen-byte format, a zero-length data chunk and an odd unknown chunk after it. The frame count and PCM length are zero, but the file still has headers and a final pad. Continue the chunk walk after data exactly as for nonempty audio. Do not use a zero payload length as a signal to ignore the rest of the supplied file.

Use \texttt{s28-1} and stop at \texttt{parse\_return}.

\paragraph{Observe} The fifty-eight-byte container passes with zero frames, PCM offset forty-six and PCM length zero.

\paragraph{Check} Is a zero-byte file a valid empty-audio input?
\begin{itemize}
\item[A.] Yes; zero frames require no description.
\item[B.] Only when its extension is wav.
\item[C.] No; empty audio still needs a valid container.
\end{itemize}
