\section{Step 11 Prepare the answer
  message}\label{001-console-calculation-s11-step-11-prepare-the-answer-message}

The input syscall left a number in \$v0; the upcoming output syscalls
need service selectors there. \$t0 keeps the arithmetic result while
\$a0 and \$v0 prepare the next requests.

\subsection{Write or
  inspect}\label{001-console-calculation-s11-write-or-inspect}

Append the address load for the answer message.

\MARSCodeLabel{MIPS assembly}
\begin{minted}{mars-idea}
report:
    la $a0, answer
\end{minted}

\subsection{Expected
  observation}\label{001-console-calculation-s11-expected-observation}

\$a0 now identifies the answer prefix. \$t0 still contains the
arithmetic result.

\subsection{Check your
  understanding}\label{001-console-calculation-s11-check-your-understanding}

Why keep the arithmetic result in \$t0 here?

\begin{itemize}
  \tightlist
  \item
        \textbf{A} \$t0 is the only register that can hold integers.
  \item
        \textbf{B} String output reads every register automatically.
  \item
        \textbf{C} Subsequent syscall setup will overwrite \$v0.
\end{itemize}
