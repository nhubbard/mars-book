\section{Step 31 Check open and read failures separately}\label{crc-s31}

Run a missing-file fixture, then an existing file with a read failure after four bytes. A valid descriptor exists only in the second case. The read-error result discards the partial checksum as a public result while still releasing the descriptor.

Use \texttt{s31-1}, \texttt{s31-2}. The CLI checks install explicit in-memory files and read/error controls. Ordinary IDE files do not force these short-read or failure conditions.

\subsection{Expected observation}
Missing input returns status one with no read/close; an error after a valid prefix returns status two and closes the opened handle.

\Needspace{11\baselineskip}
\subsection{Check your understanding}
May a partial raw state be reported as a successful file checksum?

\begin{itemize}
  \item \textbf{A} No; a read failure has its own status and zero checksum.
  \item \textbf{B} Yes, if at least one byte was read.
  \item \textbf{C} Only when the buffer is full.
\end{itemize}
