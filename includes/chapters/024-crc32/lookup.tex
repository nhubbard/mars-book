\section{Replace eight steps with one table entry}
The eight-step operation is deterministic. For each possible low byte \(i\), compute
\(T[i]=F^8(i)\), treating the remaining state bits as zero. There are 256 possibilities,
so the table occupies 256 four-byte words, or 1024 bytes. Build each entry from its
index, not from whatever value previously occupied its destination word.

For one byte \(b\), the table update is
\[
  r'=(r\mathbin{\gg}8)\mathbin{\oplus}
  T[(r\mathbin{\oplus}b)\mathbin{\&}255].
\]
The low-byte index determines the feedback generated during the eight shifts. The
upper 24 bits move down by eight and are combined with that feedback. XOR's linearity
allows these contributions to be combined after the lookup. The index mask is required:
XORing a byte with a state does not itself clear the state's higher bits.

Multiply the index by four to obtain its byte offset, then add it to the full table
pointer. Loading a table word is a separate width decision from forming its address.
The illustrated routine uses \texttt{lwu} to retain an unsigned 32-bit table value.
An ordinary \texttt{lw} followed by explicit zero extension is also correct; allowing
its sign extension to enter a doubleword XOR is not.

Test the initializer and the updater independently. Supplying an independently computed
table to the updater prevents two matching errors from concealing each other. Checking
all 256 initialized words exposes a missing final entry that a small test message may
never index. Guard bytes establish that the initializer wrote exactly its selected table.
