  \begin{minipage}{\linewidth}
    \small
    \begin{enumerate}
      \setlength{\itemsep}{2pt}
            \setlength{\parsep}{0pt}
      \item The original nine-byte message, \texttt{123456789}, returns raw state \texttt{0x340bc6d9} in \texttt{v0}. This update function has not applied the final complement. The displayed leading zeroes reflect the full register width; the CRC state uses 32 bits.
      \item The changed message returns raw state \texttt{0x2370d29a}. Compare complete states at the same boundary. A changed state here is a property of this example; it does not make CRC a cryptographic integrity check.
      \item The original input begins \texttt{31 32 33 34 35 36 37 38 39}. The following \texttt{a5} bytes are allocation padding, not part of the nine-byte input interval.
      \item The changed input begins \texttt{30 32 33 34 35 36 37 38 39}. Only bit zero of the first byte changed. Both input intervals are read-only in the checked execution.
      \item Controls show count nine, initial state \texttt{ffffffff}, bit-kernel selector zero, and a saved \texttt{raw\_result} still $-1$. The caller stores the return afterward. Finalizing the original raw state with XOR \texttt{ffffffff} gives \texttt{cbf43926}.
    \end{enumerate}
