\section{Compare implementations and design further tests}
A correct parser can use a moving pointer or an integer index into the body. It
can accumulate the header checksum while decoding fields or scan the header again
once the structural checks pass. These choices change instruction counts and load
counts. They do not change the returned fields or the caller's permitted input
interval. Compare counts on the same complete packet, include both empty and
maximum payloads, and state whether assembly and session setup are excluded.

A faster loop is useful only after it preserves the interface. A speculative read
past the available end is a contract failure even if the byte is mapped and the
extra work reduces a branch count. Conversely, the grader should not reject a safe
wider load merely because the example uses byte loads. Explain the alignment and
whole-width bound of each proposed optimization.

\begin{MARSExercise}{A checksum collision}
  Starting from the default packet, increase one payload byte by one and decrease
  another by one without wrapping either value. Predict the checksum result, payload
  sum, and reported fields before running the parser. Explain which changes this
  checksum cannot distinguish. A later CRC exercise introduces a different error
  check; neither check by itself authenticates a message.
\end{MARSExercise}

\begin{MARSExercise}{A caller with two packets}
  Put two valid packets next to one another and pass the combined available count.
  After a successful call, form the next pointer with full-width addition and subtract
  the consumed count from the available count. Call again with a separate output
  record. Retain the original input until both returned payload slices have been
  used. Specify how the caller responds to each negative status before implementing
  this variation. The submitted single-packet function keeps its original contract.
\end{MARSExercise}

\begin{MARSExercise}{Change the format deliberately}
  Design a revision with a larger payload limit or a multi-byte checksum. Write the
  new field layout, error priority, sum-width bounds, and input domain first. Decide
  whether a version change is needed. Updating one limit constant alone is not a
  complete revision of the parser or its checks.
\end{MARSExercise}
