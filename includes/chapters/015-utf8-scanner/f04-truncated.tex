    \small
    \begin{enumerate}
      \setlength{\itemsep}{2pt}
            \setlength{\parsep}{0pt}
      \item This fixture changes only the final chunk length from 4 to 0. Its offset remains 7 and its final flag remains set. The first three calls therefore accept the same seven-byte prefix as the valid demonstration. The stop follows the fourth call, which supplies no new bytes.
      \item \texttt{\$v0 = -2} reports truncation and \texttt{\$v1 = 0} confirms that this empty call accepted nothing. Finality makes the missing continuation an error. The same empty call with a non-final flag would leave the pending stream active.
      \item The state is $[7,2,1,128,191,4,-2,7]$. One continuation remains pending from the lead at offset 4. Error 7 names the end of the supplied stream, not an offending byte that was read. Count stays 2 because the incomplete four-byte sequence has not produced a scalar.
      \item The mapped input still contains \texttt{f0 9f 99 82}; the first three of those bytes have been accepted. Byte \texttt{82} at \texttt{0x10010053} could complete the sequence, but the caller offered zero bytes at that pointer. Its visibility in the debugger does not include it in this call. The execution-read trace confirms that the final empty call reads state and command metadata, with no input-byte read.
    \end{enumerate}
