\section{Step 11 Generalize the byte-order
argument}\label{002-single-pixel-s11-step-11-generalize-the-byte-order-argument}

Byte order maps a multibyte value to addresses. It does not change the
numerical definition of the RGB fields. In big-endian memory, offset
zero would select the highest byte of this word, which Bitmap Display
ignores as a color component.

\subsection{Write or
inspect}\label{002-single-pixel-s11-write-or-inspect}

Use the byte-order table to predict the result of the same sb in
big-endian memory. Then write an equivalent free-writing solution for
the published little-endian contract. Do not change the lesson
environment while comparing its expected output.

\subsection{Expected
observation}\label{002-single-pixel-s11-expected-observation}

A big-endian offset-zero update would produce 0xff336699 while leaving
the low-24-bit RGB color unchanged. This is a prediction outside the
graded little-endian environment; later byte-order exercises will
execute both configurations.

\subsection{Check your
understanding}\label{002-single-pixel-s11-check-your-understanding}

Does the same byte offset always identify the same RGB channel in both
byte orders?

\begin{itemize}
\tightlist
\item
  \textbf{A} Yes; RGB automatically reverses the address arithmetic.
\item
  \textbf{B} No; the address-to-byte mapping depends on byte order.
\item
  \textbf{C} Yes; offset zero always identifies blue.
\end{itemize}
