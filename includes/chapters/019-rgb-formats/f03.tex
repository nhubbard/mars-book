    \small
    \begin{enumerate}
      \setlength{\itemsep}{2pt}
            \setlength{\parsep}{0pt}
      \item The blue \texttt{nop} at \texttt{preview\_ready} follows the caller\textquotesingle s display loop. Both conversion returns and their result stores have completed. The displayed rows are a third layout built explicitly from component bytes.
      \item \texttt{\$v0 = 32} still holds the expansion return. This stop precedes exit, which later reuses the register for a service number. Read the return at the named boundary rather than after termination.
      \item The upper row contains 32 original colors; the lower contains their expanded values. Similar appearance does not imply equal component codes. The first lower cell is intentionally black. Row order and numerical examples carry the comparison when printed in grayscale.
      \item Original display words begin at \texttt{0x10010000}. Pixel zero is \texttt{0x00070301}, stored as \texttt{01 03 07 00}. Bitmap Display interprets a word as \texttt{00RRGGBB}; its little-endian bytes therefore run blue, green, red, zero.
      \item Expanded display words begin at \texttt{0x10010080}. Pixel zero is \texttt{0x00000000}; pixel one is \texttt{0x00080808}. These are four-byte display cells, not the two-byte RGB565 or three-byte RGB888 slices used by the conversion functions.
      \item The caller row contains count 32 and two results of 32 after its guard. The complete memory history verifies that only selected preview words and caller results were added after the conversions; original RGB, packed data, guards and masks are preserved.
    \end{enumerate}
