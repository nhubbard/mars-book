    \small
    \begin{enumerate}
      \setlength{\itemsep}{2pt}
            \setlength{\parsep}{0pt}
      \item The stop is the same \texttt{transpose\_done} boundary, before the caller stores the count. The fixtures differ only in their cache placement and blocks-per-set source-header settings.
      \item Dimensions remain \texttt{0x10} by \texttt{0x10}; the returned count is \texttt{0x100}. The cache model has not changed the program\textquotesingle s instructions or result.
      \item One block per set gives eight direct-mapped sets, still totaling 128 bytes. The replacement selector remains least recently used; with one block per set, there is no victim choice.
      \item The same 512 accesses now produce 344 misses and 168 hits, rounded to $33\%$. That is 216 more misses than the fully associative run. Cache conflicts depend on address mapping as well as traversal order; a tile alone does not guarantee fewer misses.
      \item The enlarged first output row is again $0,16,32,\ldots,240$, beginning at \texttt{0x10010440}. The oracle checks all 256 output words, untouched input and guards. Correct cache totals alone would not establish a correct transpose.
    \end{enumerate}
